# Fence and resolve Execution Attempts

`Runtime.execute` acquires an expiring fenced Execution Claim and returns an Execution Attempt containing branded Attempt and Run IDs, a single-consumer `AsyncIterable` of optional ephemeral Signals, a `PromiseLike` outcome, and an abort convenience; execution does not depend on Signal consumption, the host owns claim renewal and retry scheduling, claim loss cancels active work, and stale or late results cannot perform durable operations. `Signal.text` projects model text deltas by consuming that same Signal stream, so it cannot be used concurrently with direct Signal iteration; SSE, AG-UI, replay, and fan-out remain adapter concerns because core Signals are process-bound and not reconnectable. Attempt outcomes use the `type` discriminant `completed | suspended | failed | interrupted | aborted`; all but interruption commit a self-contained Run Result with typed variant data but no Transcript or Message Entries, while interruption records its reason, relinquishes the claim, closes Signals, and leaves the Run nonterminal; a small exhaustive match helper complements ordinary `switch`, and Defects reject the outcome and terminate Signals with the same named Error. Abort cooperatively cancels active Model and Tool work and commits through guarded finalization, with an already-entered terminal finalization winning the race; an Agent Client preserves its Agent's static Tool Signal and Tool Suspension types, while dynamic Tool Providers contribute an explicit unknown dynamic-tool branch rather than widening every static Tool to `any`.

Expected absence or rejection of Model provider credentials produces an Authentication Required Interruption rather than a Failure or Defect. The Execution Attempt records the reason, relinquishes its claim, and resolves without committing a terminal Run Result; after explicit host-driven authentication, the host may call `Runtime.execute` for the same Run. Unexpected authentication implementation errors, malformed provider responses, credential-store exceptions, and invariant violations remain Defects.

A matching Model adapter's declared inability to replay a Content Part because required Provider Data is absent or its version is unsupported produces a Provider Compatibility Interruption. The Execution Attempt follows the same nonterminal interruption path, allowing the host to install a compatible adapter and explicitly execute the same Run again. Silently degrading the replay is prohibited; malformed data that passed earlier validation is a Defect rather than a compatibility outcome.

Effect AI availability errors explicitly classified as retryable, including rate limits, transport failures, and provider-internal failures, produce a Provider Unavailable Interruption. Core preserves a provider-supplied retry time when present, records the interruption, and relinquishes the Execution Claim without sleeping or retrying. The host, its Driver, or an optional integration may schedule a later `Runtime.execute` using these primitives; retry policy is not part of the Machine.

Quota exhaustion also produces a Provider Unavailable Interruption because account action or a quota reset can make the same Run viable. Core preserves a provider-supplied reset time and distinguishes this condition from automatically retryable failures; neither the Machine nor a generic retry integration retries quota exhaustion without host policy.

A content-policy rejection before any completed Model Response commits a terminal Model Failure. This is an expected declared outcome rather than a Defect, but it does not use the nonterminal interruption path because unchanged re-execution cannot make progress.

Provider `invalid-request` or `invalid-user-input` errors likewise commit a terminal Model Failure when the canonical Model Request was valid but must change before the provider can accept it. If the adapter itself generated an invalid provider payload, the Attempt rejects with a Defect instead of attributing the bug to the Model or caller.

A declared inability to translate a valid canonical Tool or structured-output schema for the selected provider produces a Provider Compatibility Interruption. The Attempt records the capability mismatch and follows the nonterminal interruption path so a later compatible provider or Agent composition may execute the same Run.

Declared invalid-output and structured-output errors produce a Model Output Interruption when another sample may succeed. The interruption preserves usage incurred by the failed invocation but commits no Model Response; retry timing remains host policy. Adapter decoding bugs and invariant violations remain Defects even when retrying might mask them.

Effect AI `UnknownError` values and bridge outcomes that should be impossible under Commissary's invocation contract reject the Execution Attempt as Defects. Provider adapters must classify known provider conditions explicitly; core does not record a clean Failure or Interruption by guessing at an unknown condition.

Missing Artifact Store configuration when an invocation must read or persist file content produces an Artifact Storage Required Interruption. The Attempt preserves incurred usage, commits no partial Model Response, relinquishes its claim, and permits explicit re-execution after the host supplies the dependency; no inline fallback is allowed.

Each Execution Attempt owns an internal Effect Scope for selected Effect AI Models and other attempt-local execution resources. It acquires each selected Model service at most once, reuses it across that Attempt's model-and-Tool loop, and releases it automatically on completion, suspension, failure, interruption, abort, claim loss, or Defect; a later Attempt reacquires its own services. A Commissary Instance does not retain these scoped resources and needs no explicit close operation.
