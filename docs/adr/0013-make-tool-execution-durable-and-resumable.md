# Make Tool execution durable and resumable

`Tool.define` accepts a literal name plus Standard Schema values for input, output, and optional Failure data, infers the handler's input and all declared outcomes without explicit generics, and exposes `Tool.Input`, `Tool.Output`, and `Tool.Failure` type helpers; known static Tools retain their literal identities, while `Tool.dynamic` is the explicit escape hatch for runtime-discovered MCP-like definitions. A handler receives validated input and one fixed Tool Execution Context, captures application clients through its factory, returns a successful output directly, and uses branded `Tool.failure` or `Tool.suspend` helpers for other outcomes; a stable Tool Call ID and idempotency key survive process-bound Tool Attempts. Suspension is enabled only by a configuration containing a resume-input Codec, continuation Codec, and resume handler, which also exposes `Tool.ResumeInput`; `Runtime.resume` validates and durably admits that input without execution, and the next `execute` rerenders the Agent and resumes only after private compatibility checks succeed, otherwise producing a Stale Agent Interruption.

For Effect AI-backed Models, the bridge converts installed Commissary Tools into handler-free Effect AI dynamic Tool definitions using their Standard JSON Schemas and invokes the language model with Tool Call resolution disabled. Effect AI owns provider-specific Tool definition translation and Tool Call response decoding, while the Commissary Machine alone persists, validates, executes, suspends, resumes, and commits Tool Calls before the next model invocation.

Provider Tools participate in ordinary Agent Tool composition but carry a distinct provider execution owner. The Effect AI bridge passes them through as provider-defined Tools and the provider executes them inside its Model invocation; they do not create Commissary Tool Attempts, invoke Tool execution Hooks, or support core idempotency, suspension, or resume. Provider Tool identity and Model compatibility remain validated rather than being hidden in Model options.

When a Provider Tool causes the Model to return the provider-neutral `pause` Finish Reason, the Machine commits that response and advances to the next Step in the same Run. This is a provider-requested continuation, not a Tool Suspension, Interruption, retry, or completed Run, and existing stopping policy still bounds the loop.

Provider Callback Tools also participate in ordinary Tool composition. Their provider package and Effect AI define the provider-specific call and result schemas, while the host supplies the handler through the provider package's pure-JavaScript constructor. Effect AI's automatic callback resolution remains disabled: the bridge maps the decoded provider call into a durable Commissary Tool Call, the Machine invokes the callback with ordinary Tool validation, Hooks, idempotency, Failure, suspension, and resume semantics, and a later Model invocation translates the committed result back into the provider-specific format.
