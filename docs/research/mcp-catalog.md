# Official remote MCP servers: gateway reachability catalog

Scope: vendor-hosted remote MCP servers for the 20 candidates. Sources are vendor docs, official READMEs, and live `/.well-known/oauth-authorization-server` (or `oauth-protected-resource`) metadata fetched during this research session. "unconfirmed" means the fetched primary source did not state it.

Legend for the registration column:
- **CIMD**: AS metadata sets `client_id_metadata_document_supported: true`.
- **DCR**: AS metadata publishes a `registration_endpoint`.
- **Pre-reg**: docs say you must create an OAuth app/connector and use its client ID and secret, or the AS publishes no registration endpoint.
- Absence of a field in AS metadata means "not advertised", not "forbidden".

## Candidates with no official remote server found

None. All 20 have an official hosted remote endpoint. Some are only partly documented, and each is marked above.

## Notes

1. **Registration method, from live AS metadata.** Shown in the table as CIMD/DCR. Two cases conflict with the docs, so the docs govern for the gateway design:
   - Asana publishes a registration endpoint but its docs say to pre-register.
   - Supabase publishes no well-known metadata at the host, but its docs say DCR is the default.
2. **Self-registering in practice (CIMD or DCR advertised):** Linear, Notion, Sentry, Cloudflare, PostHog, Context7, Exa (CIMD + DCR). Also Atlassian, Stripe, Figma, Vercel, Neon, Zapier (DCR only). Supabase (DCR per docs).
3. **Pre-registered OAuth app required:** Slack (no DCR; Marketplace or internal apps only), HubSpot (connector client ID and secret), Google Workspace (own Google Cloud OAuth client), GitHub (GitHub App or OAuth App per host). Asana is treated as pre-registered pending confirmation.
4. **Client allow-lists and admin gates:**
   - Vercel: only AI clients reviewed and approved by Vercel.
   - Slack: Marketplace or internal apps only.
   - Notion: workspace admin "Only from approved list" setting for AI apps.
   - Atlassian: admin controls on which tools and domains may connect via OAuth 2.1. A gateway would need an admin to add its domain, or it might be blocked. Atlassian's default for custom domains is unconfirmed.
   - Google: admin gating unconfirmed.
5. **Static keys or PATs accepted as bearer or header:** GitHub (PAT), Linear (API key or bearer token), Notion (MCP token from the Developer portal), Stripe (agent API key), Atlassian (API tokens, admin opt-in), Context7 (API key), Exa (`x-api-key` or bearer), Upstash (developer API key), Neon (API key), Sentry (`Sentry-Bearer` in the Worker README; hosted endpoint unconfirmed).
6. **Transport:**
   - Streamable HTTP only: Slack, Zapier (SSE explicitly not supported), Upstash, HubSpot, Cloudflare (`/sse` is an alias for Streamable HTTP).
   - Streamable HTTP documented as primary: Linear. Its SSE endpoint is unconfirmed.
   - Legacy SSE endpoints: Asana V1 (`/sse`, deprecated, shutdown stated as 5 Aug 2026). Atlassian v1 is superseded by v2 per its docs; its SSE path was not verified in this session.
   - Unconfirmed in fetched docs: Notion, Sentry, Stripe, Figma, Google, Vercel (inferred from client config), PostHog, Context7, Exa, Asana v2, Supabase (`streamable_http` in exports).
7. **Method limits.** Client-side features (CIMD, DCR) were read from AS metadata at the host. Gateway-specific policies (admin allow-lists, per-client approval) can exist outside what is public. Items marked unconfirmed should be tested against a real tenant before design decisions depend on them.
8. **Docs found stale or conflicting.** Atlassian's v1 to v2 migration and Asana's V1 shutdown date are both stated in their own docs. Use the current v2 endpoints.
